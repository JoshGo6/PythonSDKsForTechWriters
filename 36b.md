# Lesson 36: curl vs SDK calls — reading raw API behavior

## Terminology and Theory

**`curl`** is a command-line tool that sends HTTP requests and prints the raw response. It’s the **lowest common denominator** for seeing exactly what an API returns — no SDK abstraction, no helper objects. When you’re documenting an API, you need to understand the raw behaviour because that’s what developers who don’t use an SDK will see.

**Raw API call** — a direct HTTP request made with `curl` (or a similar tool like `httpie`, `wget`, or a REST client). The response includes the status line, headers, and body (often JSON).

**SDK call** — a method in a Python library (like `PyGithub`) that *does the same HTTP request under the hood* but returns a convenient object (e.g., a `Repository` instance) instead of raw text.

When you compare them:

*   The **URL** and **HTTP method** are the same.
*   The **authentication** (a token) is the same — the SDK just reads it from your environment or code and adds the right `Authorization` header.
*   The **response body JSON** is **identical** — the SDK parses it into objects.
*   Some **headers** (like `Link` for pagination) are handled automatically by the SDK, but you can still inspect them through properties like `PaginatedList.totalCount` or by looking at the raw response object if the SDK exposes it.

Understanding the raw curl equivalent gives you a mental “blueprint” of what the SDK is doing. When you read an SDK’s source code or docs, you can recognise the underlying HTTP call underneath.

> [!note]
> In this lesson we **do not make real HTTP requests from Python**. We work with **provided curl‑style JSON strings** to practise parsing and explaining API behaviour. Lesson 37 will introduce the `requests` library for making HTTP calls programmatically.

### Pagination in raw API responses

Many GitHub REST endpoints return a **list** of items (like repos, issues, commits) in pages. The raw response includes a `Link` header that tells you if there are **more pages** and where to find them.

Example `Link` header:

```
<https://api.github.com/user/repos?page=2>; rel="next", <https://api.github.com/user/repos?page=5>; rel="last"
```

This is how a `curl` user discovers pagination. The SDK hides this by giving you a `PaginatedList` that fetches new pages automatically as you iterate.

## Syntax Section

To work with the raw JSON body from a curl response, you already know the tools:

*   `json.loads(json_string)` — parse a JSON string into Python lists/dicts.
*   `response_dict["key"]` and `list_of_dicts[i]["key"]` — navigate the structure.
*   `for item in list_of_items:` — iterate through a list of objects returned by the API.

To extract a **pagination URL** from a header string, we can use a simple regular expression with `re.search`:

```python
import re

link_header = '<https://api.github.com/user/repos?page=2>; rel="next"'
match = re.search(r'<([^>]+)>;\s*rel="next"', link_header)
if match:
    next_page_url = match.group(1)
```

However, in a real script you would usually **avoid** parsing raw headers yourself — the `requests` library or an SDK provides better tools. Here we do it solely for the purpose of understanding what’s happening.

## Worked Examples

### Example 1 – Parsing a repo list JSON string

Suppose a `curl` call to `https://api.github.com/users/octocat/repos?per_page=2` returned this JSON body as a string:

```json
[
  {"name": "boysenberry-repo-1", "private": false, "html_url": "https://github.com/octocat/boysenberry-repo-1"},
  {"name": "git-consortium", "private": false, "html_url": "https://github.com/octocat/git-consortium"}
]
```

We can parse it and print a small doc‑style summary for each repo:

```python
import json

raw_json = '''
[
  {"name": "boysenberry-repo-1", "private": false, "html_url": "https://github.com/octocat/boysenberry-repo-1"},
  {"name": "git-consortium", "private": false, "html_url": "https://github.com/octocat/git-consortium"}
]
'''

repos = json.loads(raw_json)

for repo in repos:
    visibility = "private" if repo["private"] else "public"
    print(f"Repository: {repo['name']} ({visibility}) – {repo['html_url']}")
```

Output:

```
Repository: boysenberry-repo-1 (public) – https://github.com/octocat/boysenberry-repo-1
Repository: git-consortium (public) – https://github.com/octocat/git-consortium
```

### Example 2 – Simulating pagination with a `Link` header

Often the raw response includes a `Link` header that tells you there are more results. In a real `curl` session you would see this header printed above the body. For this exercise we isolate the header value as a string.

Here’s a typical scenario:

*   `curl` fetches page 1 with `?per_page=2`.
*   The response JSON body contains 2 repos.
*   The `Link` header contains a `rel="next"` URL pointing to page 2.

We can write a script that parses the JSON, prints the repo names, and then tells the user whether there is a next page — and, if so, prints the URL they would use with `curl` to fetch it.

```python
import json
import re

# Simulated raw data from a curl response
link_header = '<https://api.github.com/user/repos?page=2>; rel="next"'
raw_body = '''
[
  {"name": "repo-alpha", "html_url": "https://github.com/octocat/repo-alpha"},
  {"name": "repo-beta", "html_url": "https://github.com/octocat/repo-beta"}
]
'''

repos = json.loads(raw_body)

print("Repositories on this page:")
for repo in repos:
    print(f"  - {repo['name']}")

# Check for a next page
next_match = re.search(r'<([^>]+)>;\s*rel="next"', link_header)
if next_match:
    next_url = next_match.group(1)
    print(f"\nThere are more results. To fetch the next page with curl, use:")
    print(f"  curl {next_url}")
else:
    print("\nThis is the last page.")
```

Output:

```
Repositories on this page:
  - repo-alpha
  - repo-beta

There are more results. To fetch the next page with curl, use:
  curl https://api.github.com/user/repos?page=2
```

> [!info]
> The **SDK equivalent** for the whole endpoint is:
> ```python
> repos = user.get_repos()
> for repo in repos[:2]:
>     print(repo.name)
> ```
> The SDK automatically follows pagination internally; you don’t need to parse the `Link` header. But knowing how the raw header works lets you document pagination behaviour correctly when writing about the REST API.

## Quick Reference

```python
# Parse a JSON string into Python data structures
import json
parsed = json.loads(json_string)

# Access a value in a list of dictionaries
for item in parsed:
    print(item["key"])

# Extract a "next" pagination URL from a Link header string
import re
match = re.search(r'<([^>]+)>;\s*rel="next"', link_header_value)
next_url = match.group(1) if match else None

# Use the page URL to inform the user
if next_url:
    print(f"Next page: {next_url}")
```
